# Final independent A legal-span review

Read-only source review, 4 October 2026. References below are to the source inspected before the implementer addressed the reported findings. No remote commands or new tests were run by this reviewer. Fixes reported as in progress by the implementer have not been independently reverified here.

## Important findings

1. **Generic and continuity-removal controls still receive continuity features.** `legalspan/model.py:89-98` and `:187-189`: the mode/flag only disables the attention-score bias. `strength = (alpha * counts).sum(...)` is still passed to both the residual gate and output copy gate. Learned nonzero gate weights therefore let the purported generic route use observed-history continuity, confounding the proposed full-versus-generic comparison and the continuity-removal ablation. Disable continuity evidence at every consumer when the mode is generic or `use_continuity=False`; add a gate-sensitive regression, since zero-initialized gate weights conceal this issue.

2. **Token-window role features can disclose future suffix text.** `legalspan/data.py:89-99`: roles are computed over the entire document, then sliced at a random token cut. A cut inside a multi-token `Section` assigns the visible partial prefix the statutory-cue role because its unseen suffix completes the word. A whitespace run can similarly receive a newline role from an unseen newline. This violates the prompt-only feature contract in the approved proposal, even though the model's fixed-role future-perturbation test passes. Derive these roles from the actual observed prefix bytes and preserve byte offsets across partial UTF-8 boundaries, or restrict cuts to safe piece boundaries. Rebuild the prepared data in a new versioned cache; add a bisected-cue regression. The completed cache made with this implementation must not be reused for substantive training.

3. **A checkpoint can skip a required candidate after interruption.** `legalspan/train.py:132-136`, consumed by `legalspan/pipeline.py:253-260`: latest is committed before due milestone candidates. If a save step crosses the half-budget milestone and execution stops between the writes, resume begins past the milestone and its crossing condition never runs again. The pipeline subsequently attempts to load a missing half-budget checkpoint; `FileNotFoundError` also escapes its evaluation-failure handler. Publish due snapshots before advancing the resumable checkpoint, and add an interrupted-save regression. The analogous C implementation already uses this ordering in `cs781/train_c.py:239-243` and tests it in `tests/test_train_c.py:97`.

4. **The automatic experiment ladder skips the approved screening decision.** `legalspan/pipeline.py:234-248`: all three pilots train, but their generations are never evaluated, and full-route substantive training starts before the matched control's full-dev error analysis. The approved proposal at `outputs/CS781_A_Novelty_Proposal_20261004.md:136-138` requires that analysis before substantive candidate selection, with a separate repetition intervention if repetition dominates. Implement a persisted pilot/control-dev screening gate before selecting the substantive candidate, or document an explicit accepted change to the experiment ladder. The current ordering also spends a full substantive budget on generic-route rather than using its screening evidence to choose the informative subset.

## Acceptance and coverage gaps

- **CUDA/BF16 route probabilities and cache parity:** `tests/test_legalspan_model.py:46-69` checks CPU/FP32 only; `scripts/verify_a_gpu.py:15-32` checks a full-mode optimizer step. In CUDA autocast, the `.float()` arguments to the `bmm` calls at `legalspan/model.py:85,87` do not by themselves force FP32 matmul. Full mode obtains FP32 score promotion from its continuity addition, but generic/continuity-disabled modes can reach `:95` with BF16 scores and softmax probabilities. Explicitly perform probability softmax in FP32 and verify normalized copy/vocabulary probabilities, finite gradients, and boundary-plus-multiple-token cache parity under the actual CUDA/BF16 inference path for full and generic modes.
- **Complete public context preflight:** `legalspan/data.py:101-107` validates held-out prompt/reference lengths; `scripts/run_a_legalspan.sh:30-41` obtains the public test and launches training without an own-tokenizer context scan. `legalspan/generate.py:17-24` discovers public context exhaustion only during generation after training. The approved proposal at `outputs/CS781_A_Novelty_Proposal_20261004.md:46` requires complete dev/public prompt-plus-generation coverage before freezing 8192 tokens. Save coverage evidence for every actual public ID, including the declared generation reserve, and fail launch if that capacity contract is not met.

## Assessment

Do not begin substantive training with the inspected source/data cache. Resolve findings 1-3 and the CUDA/BF16 and actual-public coverage checks, and reconcile the experiment-ladder deviation before launch. The reviewed launcher selects GPU1 and contains no job signals; this review makes no claim about current remote process state.
