# Phase 5: why the statute-identification systems changed

The task is multi-label: a judgment may cite several statutes, so a system predicts a binary vector rather than choosing one class. We started with the inherited Phase 1 B1 representation and asked whether a small trainable adaptation could transfer to this task. The [LoRA run](variants/b1_lora/README.md) uses a frozen parent plus rank-8 low-rank updates, conceptually `W' = W + (alpha/r)BA`, and a statute-logit head. The [LoRMA+ run](variants/b1_lorma/README.md) changes how the low-rank module acts on the inherited representation. Both need calibrated per-statute thresholds because `sigmoid(logit) >= 0.5` is rarely a suitable universal rule under imbalanced labels.

The key weakness exposed by these initial results was document coverage. A window encoder can learn a meaningful local representation while missing a citation that appears much later. We therefore tried three different responses. [Statute-wise GRU memory](variants/b1_statute_gru/README.md) aggregates window evidence recurrently for each label; [position-aware queries](variants/b1_position_queries/README.md) allow label-specific attention over passage position; and [sparse-guided selection](variants/b1_sparse_guided/README.md) uses lexical cues to choose passages for the neural reader. Their finished Codabench macro-F1 scores were 0.2238, 0.2254, and 0.2417, respectively, below the 0.2554 B1 LoRA result. These numbers do **not** prove that recurrent memory or position information is intrinsically harmful: the implementations also differ in optimization and evidence selection, and we do not have controlled repeated runs.

The strongest submission kept *full-document lexical evidence* alongside the neural branch. A TF-IDF representation with unigrams/bigrams feeds a one-vs-rest sparse classifier. Its document coverage and the B1 contextual probabilities are combined at the prediction level, `p = 0.9 p_sparse + 0.1 p_B1` in the archived fixed-blend run. Grouped official-train calibration supplies thresholds; official dev and Codabench remain evaluation sets. The [hybrid](variants/b1_sparse_hybrid/README.md) scored 0.3949, whereas a [five-fold calibration-CV variant](variants/b1_sparse_hybrid_cv/README.md) scored 0.3944. The gain over the pure neural branch is *consistent with* restored long-document statute-phrase coverage; it is not an isolated causal estimate. The archived hybrid report explicitly leaves course-method eligibility unverified, so a code reviewer should not mistake the top score for a method-approval decision.

The [submission map](SUBMITTED_VARIANTS.md) provides every distinct scored export and the supplied Codabench screenshot. Each variant has exact source hashes, a later explanatory notebook clearly distinguished from the historical runner, a PDF/LaTeX methodology note, and its original prediction ZIP when found. Our analysis here is a post-run interpretation of those artifacts, not an invented training diary.
